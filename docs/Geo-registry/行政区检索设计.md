# 行政区检索设计

日期：2026-09-15  
状态：核心检索升级已实现（2026-09-16），完成项与后续可选优化见文末清单。前面的现状章节保留为升级前的问题记录。

## 1. 目标与原则

让用户通过地名、上级地区、完整地址或拼音找到正确的地域实体，并以稳定的 `place_id` 选择和保存。

- 默认理解自然输入，不要求学习搜索语法。
- 完整名称与行政层级是事实数据；简称、折叠是展示行为。
- 同名不等于同一实体，名称相近也不等于地域范围相同。
- 检索结果必须解释“是什么地方、属于哪里、能否选择”。
- 行政区检索优先服务资料地区选择；聚落、自然地理及其他地点可作为独立类型扩展，不能混用层级语义。

## 2. 现状与问题

代码依据：

- 地理服务检索：`geo-registry/app/geo/places.py` 的 `search_places`。
- 接口参数与返回：`geo-registry/app/handlers/geo.py`。
- 本地后备实现：`backend/app/geo/places.py`。
- 前端选择器：`frontend-legacy/js/components/GeoLocationPicker.js`。
- 前端地区展示：`frontend-legacy/js/shared/location-display.js`。

| 现状 | 问题 |
| --- | --- |
| 对三个名称字段使用整段 `ILIKE '%q%'` | 不理解上级地区与目标地名组合 |
| 按层级、排序键、人口等排序 | 精确命中没有明确优先级 |
| 已存储拼音，但搜索未使用 | 拼音输入无法稳定命中 |
| 大区参与搜索，保存时拒绝大区 | 可搜索与可选择语义不一致 |
| 前端取 15 条结果 | 缺少剩余结果提示和继续查找入口 |
| 搜索序号在防抖回调内递增 | 清空、切换范围及等待防抖期间存在旧响应回填风险 |
| 网络异常统一显示数据未导入 | 用户无法判断真实失败原因 |
| 每个结果逐层读取路径及关联信息 | 重复访问公共祖先，查询数量随结果数和深度增长 |

升级前已增加完整路径名称展示和 `has_siblings` 元数据。历史 `users.location` 仍可能包含旧版去后缀文字，不能据此恢复地名。升级后的验证结果见文末；索引效果仍须通过实际查询计划确认。

## 3. 完整名称与层级折叠

### 3.1 名称规则

取消通用删后缀规则。新区、新镇、新城、乡、镇、街道、苏木及其他名称均保留地理库中的完整形式。

“松江新城”与“松江”不得通过字符串截断视为同一实体。别名匹配必须来自明确的实体别名记录，不通过删字自动建立等价关系。

### 3.2 层级折叠规则

仅在前端生成紧凑路径时跳过同时满足以下条件的节点：

1. 是行政区节点。
2. 在完整地理树中，其父节点没有其他子节点。
3. 不是用户选中的末级节点。

兄弟判断不依赖当前搜索结果、分页、筛选条件或已加载的级联列表。元数据缺失时保留该层级。根节点不因缺少父节点而自动折叠。导航用地理大区依现有产品规则隐藏，但不视为行政单支折叠。

条件示例：若上海城区在实际树中没有兄弟节点，`上海市 → 上海城区 → 浦东新区 → 张江镇` 紧凑显示为 `上海市 · 浦东新区 · 张江镇`。若选中末级就是上海城区，则保留 `上海市 · 上海城区`。

完整面包屑和级联选择仍可查看全部层级。折叠不改变 `place_id`、父子关系或保存内容。

### 3.3 数据兼容

- 有 `place_id`：以结构化路径恢复完整名称；附加地址单独保留。
- 仅有自由文本：原样显示，不猜测补字或地域实体。
- 地理服务暂不可用：使用已有文案作为降级，并允许重试。
- 新写入数据应以完整名称及独立附加文字为准；旧数据修复须另行提供可审阅的迁移方案。

## 4. 输入与匹配

| 输入 | 预期解释 |
| --- | --- |
| 张江 | 地名检索，展示全部符合条件的实体 |
| 上海 张江 | 目标名称匹配张江，祖先路径匹配上海 |
| 浦东新区张江镇 | 根据已知地名及父子关系解析连续地址 |
| zhangjiang / zhang jiang | 规范化拼音后匹配同一候选集 |
| 松江新城 | 优先完整名称命中，保留完整实体含义 |

### 4.1 规范化

统一首尾空白、连续空白、拉丁字母大小写和全半角形式；保留原始输入供界面回显。拼音使用独立规范化字段支持有空格与无空格形式。简繁体、历史名称、外文别称通过显式别名机制逐步支持。

普通检索、独立引号精确检索及国家名称解析均支持现有 `name_zh`、`name_en`、`name_local` 字段。中文和英文均可输入，英文名称及国家代码不区分大小写；字段无对应译名时不自动翻译或补造别名。首版不启用别名机制，后述别名排序仅为后续预留。

SQL 参数仍使用绑定参数；普通输入中的 `%`、`_` 必须按字面转义，不能意外成为通配符。限制查询长度、词数、分页大小和解析候选数量。

### 4.2 多词与连续地址

带空格输入优先进行目标名称与祖先路径联合匹配，允许上级地区省略中间层级。连续地址按地名词典生成候选分段，再验证父子关系；不只靠行政后缀正则切词。

有多种合理解释时保留候选及其完整路径，不自动选中。不将没有匹配的地址尾部默默丢弃：提示用户该部分未识别，可补充为附加文字。

第一阶段优先支持带空格组合；连续地址解析作为独立后续能力。

### 4.3 排序

先应用明确的地区、类型和可选择性过滤，再按以下顺序排序：

1. 完整名称精确命中。
2. 经确认的别名精确命中。
3. 名称前缀命中。
4. 名称包含命中。
5. 拼音命中；在拼音输入场景中提高对应匹配优先级。
6. 后续可选的纠错匹配，明确标为近似结果。

同一匹配档内依次考虑上级路径匹配度、已选范围、行政类型及可用的人口信息，最终用稳定 ID 打破平局。人口只作辅助，不让人口较大的模糊命中压过小地区的精确命中。

首字母搜索容易产生大量歧义，后于完整拼音实施。不得仅按名称去重；跨数据源合并需有可靠实体映射。

## 5. 搜索界面

每条结果使用两行结构：第一行完整名称与类型标签，第二行上级路径。名称与路径可高亮命中词；同名结果通过路径区分。

示意：

> 张江镇　〔乡镇〕  
> 上海市 · 浦东新区

提供地区范围与行政层级筛选。国外层级标签根据来源映射，不能简单按整数 level 套用国内省市县名称。默认资料选择结果只包含可保存实体；大区若保留，应显示“进入该范围搜索”的独立导航动作。

固定结果上限之外返回 `has_more`，显示“查看更多”或建议限定地区。输入框清空与已选地区清空应有明确行为：搜索输入和已选值分开呈现，清空已选地区使用显式动作。

状态分别处理：初始、加载中、有结果、无匹配、请求失败、地理库未就绪。失败可重试，不能把超时描述为“未导入”。

## 6. 高级语法

高级语法是可选快捷方式。首版确定使用 `country=` 和 `deep=`，暂不增加别名解析。

| 语法 | 含义 |
| --- | --- |
| `country=US` | 美国范围内检索 |
| `country=美国` | 精确解析国家名称后，转换为 US 过滤 |
| `country=US deep=0` | 美国国内地理大区，例如新英格兰 |
| `country=US deep=1` | 美国一级行政区 |
| `country=中国 deep=4 张江` | 中国四级行政区（通常为乡镇、街道）中检索张江 |
| `country="United States" deep=1` | 含空格的英文国家名称作为一个字段值 |
| `country="United States" New York` | 美国范围内对 New York 进行普通检索 |
| `country=US "New York"` | 美国范围内精确匹配完整名称 New York |
| `"松江新城"` | 精确匹配完整名称松江新城 |

`country` 接受两位国家代码（大小写不敏感）或国家节点现有 `name_zh`、`name_en`、`name_local` 的完整名称。名称只在国家节点中精确解析，得到 `iso_country` 后过滤；不调用别名表或别名映射。多个节点对应同一代码可合并，名称对应多个代码则报告歧义。代码需校验为地理库支持的代码，未知名称或代码给出错误。

`deep` 每次接受一个整数：`-1`、`0`、`1`、`2`、`3`、`4`、`5`。这里的斜杠列表表示允许值，不是多值输入语法。它是对外统一的检索层级编号，不是数据库原始 deep，也不是树中节点的实际深度。

| deep | 统一含义 | 国内示例 / GeoNames 对应 | geo_places.level |
| --- | --- | --- | --- |
| -1 | 国家 | 国家节点 | 1 |
| 0 | 国家内部地理大区，跨多个高层行政区的导航分组 | 华东、关东、新英格兰；source=macro | 15 |
| 1 | 一级行政区 | 国内通常为省级 / ADM1 | 2 |
| 2 | 二级行政区 | 国内通常为地级 / ADM2 | 3 |
| 3 | 三级行政区 | 国内通常为县级 / ADM3 | 4 |
| 4 | 四级行政区 | 国内通常为乡镇、街道 / ADM4 | 5 |
| 5 | 五级行政区 | 国内通常为村、社区（若有收录）/ ADM5 | 6 |

数据库字段保留原值，统一从 `geo_places` 检索，在一处集中维护对外映射：

- 国内 `source=ok_zh`：对外 `deep = deep_legacy + 1`。源表 `ok_zh_level4.deep` 保持 0 起算，现有导入关系仍为 `geo_places.level = deep_legacy + 2`。
- GeoNames 国家节点：对外 `deep=-1`。
- 国家内部 `source=macro` 地理大区：对外 `deep=0`，不是正式行政等级。
- GeoNames ADM1–ADM5：对外 deep 分别为 1–5；仅在确认行政节点类型后使用对应的 level 映射，不对所有地点机械执行减法。
- 居民点 PPL、自然地理不纳入这套编号；大洲暂不纳入。

国外等级表示来源中的行政等级，不保证与国内实体性质相同。不得按面包屑长度计算 deep；国家没有地理大区时直接进入 deep=1，不补造 deep=0 节点。导航分组插入、行政中间层级折叠均不改变既有行政区的 deep。某层级未收录时返回空结果，不推断生成节点。

`deep=0` 允许检索大区，但不赋予其资料保存权限。资料选择器应将其作为独立导航结果，选择后限定地区继续搜索；使用 `selectable_only=true` 的纯可选实体请求仍会排除大区。前端应区分导航查询与资料选择查询，不能把“不可保存”误报为“未收录”。

解析器识别白名单键值及剩余关键词，多条件取交集。仅带筛选条件也允许查询并分页。支持等号两侧空格。未知字段、非法 deep、空值、未闭合引号给出明确错误。重复相同条件合并，不同条件报告冲突。输出规范化筛选标签，绑定参数执行查询，禁止直接拼接 SQL。

### 6.1 分隔符与引号

条件之间使用空白分隔，首版不使用分号作为条件分隔符。双引号有两种含义，由所在位置决定：

- 字段值位置：`country="United States"` 将包含空格的名称包裹为一个值。国家名称本来就按完整名称精确解析，引号不改变其匹配模式。`country=美国` 与 `country="美国"` 等价。
- 独立关键词位置：`"New York"`、`"松江新城"` 将目标名称设为精确匹配，支持中文和英文。对规范化后的任一现有名称字段做完整值比较，不仅是词组包含匹配，不退回前缀、模糊、拼音或别名匹配。

普通关键词中的空格不强制要求引号：`country=US New York` 的剩余文字交给自然搜索；`country=US "New York"` 才是完整名称精确检索。精确名称仍可能对应多个不同实体，须返回各自的地区路径，不能自动视为唯一结果。

含空格的字段值必须用双引号。例如 `country=United States` 无法精确解析国家 United 时，应提示“国家名称无法识别；含空格的名称请使用双引号，例如 country=\"United States\"”，不能静默丢弃该条件或把整个输入当普通搜索。解析器不猜测吞并后续关键词以修复字段值。

首版使用 ASCII 双引号作为定界符；单引号按普通名称字符处理。引号内可用 `\"` 表示字面双引号、`\\` 表示反斜杠，其他不支持的转义及未闭合引号报告错误。空引号不构成有效字段值或有效精确名称。

建议逐字符分词，区分字段值、普通文本及独立精确名称，再输出结构化过滤条件和匹配模式。不要先按空格切开再猜测引号。独立精确名称与 country/deep 筛选同时生效；若伴随上级地区普通词，则按祖先路径约束处理。多个不同独立精确名称首版报告冲突，相同名称去重。

### 6.2 冲突与范围

控件、scope 和语法出现冲突时提示用户解决，不静默覆盖。未填写 country 或 deep 时不添加对应限制；不再使用 `国家:`、`层级:` 语法。

暂不提供正则、布尔 AND/OR、括号嵌套和任意字段查询。语法版本与错误码需稳定，方便后续扩展。

## 7. 接口方案（拟议）

沿用 `/api/geo/regions/search` 和地理服务 `/api/places/search`，共享检索核心；后端本地后备实现保持同一契约。

请求参数：

| 参数 | 用途 |
| --- | --- |
| `q` | 原始检索输入 |
| `scope` | 兼容现有数据范围；与国家过滤分别定义 |
| `ancestor_id` | 限定在指定节点的子树内 |
| `country` | 国家代码或现有完整名称，解析后内部使用 country_code |
| `deep` | 统一检索层级，允许 -1 至 5；0 为国家内部地理大区，独立于树路径长度 |
| `selectable_only` | 资料选择默认 true |
| `limit` / `cursor` | 有上下限的分页大小及稳定游标 |

响应保留 `items`，逐步增加 `has_more`、`next_cursor`、解析后的 `filters` 和必要的歧义提示。每项建议包含：

```json
{
  "id": 123,
  "display_name": "张江镇",
  "admin_type": "township",
  "selectable": true,
  "match_type": "name_prefix",
  "path": [
    {
      "id": 100,
      "parent_id": 90,
      "display_name": "浦东新区",
      "is_administrative": true,
      "has_siblings": true
    }
  ]
}
```

以上 ID 仅为示例。正式 `path` 返回包含目标节点的完整面包屑，紧凑路径由前端生成。现有 `path_label` 在兼容期保留。高级语法启用后增加规范化解析结果与结构化解析错误。

地区筛选使用 ID 或规范代码，禁止将展示简称作为主键。分页顺序稳定；变更查询或筛选后游标失效。

## 8. 请求生命周期与性能

### 8.1 前端

- 输入或范围变化时立即增加请求版本，然后执行防抖。
- 清空、切换范围、卸载时取消定时器与请求。
- 成功和失败回调都检查版本；过期请求不能改变结果或错误状态。
- 选择结果后读取路径同样检查版本，防止快速切换选项时旧路径回填。
- 以查询、筛选和分页参数为键做有界短期缓存；路径按 ID 复用。
- 避免选择回填与 model watcher 对同一路径重复请求。

### 8.2 服务端

- 将候选召回、排序、路径补全分离。
- 批量读取结果祖先，复用共同路径；批量计算兄弟存在性。
- 搜索路径复用不应为每个祖先额外查询不需要的 `has_children`。
- 精确与前缀匹配优先评估对应索引；包含和近似检索评估 PostgreSQL trigram 索引。
- 单字中文、短拼音及高频地名分别检查查询计划，不能假设一种索引适用全部输入。
- 地理树变更后使路径缓存失效，避免长期使用旧的兄弟信息。

先记录端到端响应时间、数据库查询次数和候选规模，再确定延迟目标。本文不宣称已经达到性能指标。

## 9. 实施阶段

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| P0 正确性 | 旧请求失效、错误状态、不可选节点、参数边界、完整名称 | 不回填过期结果，不把不可保存节点伪装成可选项 |
| P1 检索体验 | 匹配度排序、两行结果、地区过滤、带空格组合、完整拼音、更多结果 | 典型查询能找到并辨认目标实体 |
| P2 查询效率 | 批量路径、索引评估、缓存与失效 | 在实际数据规模下验证查询量与响应改善 |
| P3 扩展 | 连续地址、country/deep 高级语法、必要时纠错；别名暂缓 | 歧义可解释，旧输入与接口保持兼容 |

P2 可随性能证据提前。高级语法不阻塞自然输入体验。

## 10. 验收场景

- 精确地名排在其他包含该字符串的名称之前。
- `上海 张江` 与完整拼音能找到目标；同名地区仍可通过上级路径区分。
- `松江新城`、`新乡`、`盐城` 保留完整名称，不受删后缀规则影响。
- 无兄弟的行政中间层级折叠；有兄弟、信息未知及所选末级保留。
- 搜索筛选或分页只剩一个节点时，不能据此认定它没有兄弟。
- 快速输入、清空、切换范围和快速选择时，过期响应不回填。
- 服务失败显示可重试错误；零结果与未导入各自有独立提示。
- 单引号、百分号、下划线、超长输入及非法分页参数得到安全且可预期的处理。
- 结果超过首页上限时可以继续查找；分页无不稳定重复或漏项。
- 无结构化 ID 的旧文字原样保留；完整路径恢复后附加地址不丢失。
- 高级语法启用后，语法和筛选控件语义一致，冲突或歧义可见。
- `country=US deep=0` 查询国内大区，`country=US deep=1` 查询一级行政区，`country=中国 deep=4 张江` 查询四级行政区。
- 国内源 deep=3 与 GeoNames ADM4 均映射为对外 deep=4；原始表字段不改写。
- 没有地理大区的国家仍从 deep=1 开始列出一级行政区；大洲、PPL 和自然地理不得误入 deep=0。
- deep=0 的导航结果不能保存为资料地区；纯可选实体查询明确排除大区。
- `country=US`、`country=us`、`country=美国` 和 `country="United States"` 在现有名称字段支持时得到相同国家过滤；不通过别名扩大匹配。
- `country=US New York` 执行普通搜索，`country=US "New York"` 只匹配完整名称；中英文独立引号遵循相同规则。
- 含空格的国家值未加引号、空引号、未闭合引号及非法转义有明确错误；分号不作为条件分隔符。
