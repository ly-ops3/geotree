# 把子项目拆成独立仓库，踩了哪 5 个坑

一个功能上早就独立的子项目，物理上还赖在主仓库里是什么体验？
geotree 是我社交动态备份项目（moments-pro）下的地理服务：
Flask + PostgreSQL，提供统一 `place_id`、级联区划查询和中英文地名搜索。
自己的端口、自己的库、自己的 API，看起来早就该独立了——真动手拆才发现，
数据散在三个地方、配置在四处硬编码、连备份文件都是 MySQL 方言。
这篇记录一下拆分过程踩到的 5 个坑。

## 坑 1：先独立数据，再独立代码

拆开一看，"项目"其实不止 `geotree/` 这一个目录：

- `geotree/database/geo/` —— 代码默认的数据源目录，里面却几乎是空的
- `backend/database/geo/zh_altnames.sqlite` —— 35MB 的中文别名索引，真身住在 backend
- `backend/database/ok_zh_level4.sql` —— 国内区划种子的备份，又散在另一层

所以第一步不是建仓库，而是把散落的文件物理归位：

```
backend/database/geo/zh_altnames.sqlite → geotree/database/geo/
backend/database/ok_zh_level4.sql       → geotree/database/seed/
```

教训：**子项目独立化的第一件事永远是盘点它的隐形依赖**。
代码内聚不代表资产内聚，数据文件、种子脚本、文档都要算进"项目边界"。

## 坑 2：配置"半抽离"比不抽离更隐蔽

`config.json` 早就把 PG 连接抽出来了（host/port/name/user/password），
看起来配置化做得很干净。但 grep 一下 `GEO_DIR`，发现它在**两个文件里
各自硬编码了一遍**：

```python
# app/geo/names_zh.py
GEO_DIR = os.path.join(os.path.dirname(...), 'database', 'geo')
# scripts/geo/import_geonames.py
GEO_DIR = os.path.join(os.path.dirname(...), 'database', 'geo')  # 同款再算一遍
```

改法：在 `app/config.py` 里加 `data_dir` 配置项和 `get_geo_dir()` 函数，
三处统一收口；同时补了环境变量覆盖（`GEO_DATA_DIR`、`GEO_DB_DSN`、
`GEO_DB_HOST` 等单项）。优先级定为：

```
环境变量 > config.json > 内置默认值
```

这样三种部署形态都能活：本机开发用 config.json、服务器用 `GEO_DB_DSN`
环境变量不落密码、公开仓库用户拷 `config.example.json` 起步。

一个小坑：`load_config()` 有个 early-return 分支（config.json 不存在时
写默认值后直接返回），环境变量覆盖写岔了位置会导致这条路径跳过覆盖。
把覆盖逻辑抽成 `_apply_env_overrides(raw)` 在所有返回路径上统一调用。

## 坑 3：嵌套 git 的解绑顺序

拆分前我先在父仓库 `git add -A` 提交了快照——结果 geotree 的文件
被**提交进了父仓库**。之后 `git init` 建独立仓库，父仓库 status 里
geotree 的文件仍显示 modified，因为它已经被父仓库追踪了。

正确姿势（`--cached` 的意思是只从 git 索引里删追踪记录，
磁盘上的文件原样保留）：

```bash
# 父仓库：解除追踪
git rm -r --cached geotree
# 父仓库 .gitignore 声明这是外部目录
echo "geotree/" >> .gitignore
```

顺序不能反：如果先在父仓库 .gitignore 里加了目录但没 `git rm --cached`，
已追踪的文件照旧被追踪，ignore 对它们无效。

## 坑 4：gitignore 白名单被目录级忽略吞掉

需求：`database/geo/` 里的大文件（GeoNames dump zip、allCountries/ 目录）
要忽略，但 `zh_altnames.sqlite` 和 README 要入库。第一版写法：

```gitignore
database/geo/          # ← 错：目录级忽略
!database/geo/zh_altnames.sqlite   # 无效！
```

**Git 规则：目录一旦被整体忽略，git 不会遍历其内容，内部文件的 `!`
白名单永远不生效。** 正确写法是通配内容而不是目录本身：

```gitignore
database/geo/*
!database/geo/README.txt
!database/geo/zh_altnames.sqlite
```

验证方式：`git check-ignore <file>`，输出路径才算真忽略。

## 坑 5：以为的"PG 备份"其实是 MySQL dump

`ok_zh_level4.sql` 一直被我当 PostgreSQL 备份看，直到 diff 才发现头部
写着 `Source Server Type: MySQL`——是 Navicat 从 MySQL 导出的方言产物
（`ENGINE=InnoDB`、`int`、`varchar(255)`），PG 根本不能吃。

教训：**备份文件的"方言"要和目标库对齐**。真正的部署种子应该用
`pg_dump` 重新导出：

```bash
# 纯文本 SQL（psql -f 直接灌）
pg_dump -U postgres -d geo_registry -t ok_zh_level4 -f ok_zh_level4.pgdump.sql
# 自定义压缩格式（小一个数量级，需 pg_restore）
pg_dump -U postgres -d geo_registry -t geo_places -Fc -f geo_places.dump
```

最终 seed 目录三件套：`ok_zh_level4.sql`（MySQL 原始备份，保留当历史）、
`ok_zh_level4.pgdump.sql`（PG 部署种子）、`geo_places.dump`（主表 21.5MB）。

## 总结

拆分一个"看起来已经很独立"的子项目，真正的工作量从来不在 `git init`：

1. 盘点并归位散落的数据资产
2. 把硬编码路径收敛成三级配置（env > config > default）
3. 父仓库 `git rm --cached` 解绑 + `.gitignore` 声明外部
4. gitignore 白名单用 `dir/*` 而不是 `dir/`
5. 备份文件验证方言，部署种子用 `pg_dump` 重新产

做完这些，仓库才能真的"clone 下来就是活的"。
